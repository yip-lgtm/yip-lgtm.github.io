MCP 工具描述投毒已由理論轉為在野攻擊：代理開發環境的信任邊界究竟由誰承擔

MCP Tool Poisoning Is Now an Operational Attack: Who Owns the Agent Trust Boundary?

2026-11-05 21:00 UTC · 996 中文字 · 8346 bytes · 10 來源 · 通過品質閘

主題 / Topic

本報告回答：AI 代理經 MCP 接駁外部工具時，「工具描述」欄位實際由誰承擔信任？量化代理對被污染描述的服從率，並追蹤自動執行缺陷如何把單機投毒擴散成團隊與供應鏈事故。範圍為 2025 年 4 月至 2026 年 6 月公開披露。

This report asks who owns trust in an MCP tool description. It quantifies agent compliance with poisoned descriptions and traces how IDE auto-execution turns a single poisoned config into team-wide incidents.

核心發現 / Key Findings

  • 【機制】描述欄同時是文件欄與指令欄：MCP 規格不要求客戶端驗證、消毒或簽署工具描述；模型讀描述以決定何時呼叫工具，故兩者在協議層無結構差異。替代解釋已排除——非模型能力不足，拒答率最高的 Claude 3.7 Sonnet 仍約 34% 個案照做；亦非舊式提示注入，投毒版對用戶仍顯示正常輸出。

The protocol neither validates nor signs tool descriptions, so a description is documentation and directive at once; the most-refusing model still complied in ~34% of cases, and poisoned runs still look normal to the user.

  • 投毒成功率已基準化：MCPTox 用 45 個線上伺服器、353 個真實工具、20 個 LLM、1,348 個攻擊樣本量測，平均成功率 36.5%，最高 72.8%（o1-mini）；能力較強模型常更易受影響，作者歸因於更強的指令服從。

MCPTox measured 45 live servers, 353 tools, 20 LLMs and 1,348 attack cases: 36.5% average attack success, 72.8% peak (o1-mini), with stronger models often more susceptible.

  • 生態層污染率遠低於危害敘事：1,899 個開源伺服器掃描中 7.2% 含一般漏洞、5.5% 出現工具投毒（8 類漏洞）；67,057 個註冊伺服器僅 18 個描述可疑，且多為教學 PoC，其中 5 個屬無意工具混淆。

Empirical prevalence is far below the alarm: 5.5% tool-poisoning across 1,899 servers, and only 18 suspicious descriptions out of 67,057 registered servers.

  • 【機制】放大器是自動執行，不是投毒本身：投毒尚需人按一下；但 IDE 若自動啟動專案設定的 MCP 伺服器，惡意倉庫一條設定檔即可取得開發者完整 OS 權限。2026-05-07 披露驗證 Claude Code、Cursor CLI、Gemini CLI、GitHub Copilot CLI 四款全部在信任對話框後自動執行，且預設為肯定；Claude Code 的 headless CI 更完全跳過對話框。

The amplifier is auto-execution: all four major agentic CLIs auto-run project-defined MCP servers after a trust prompt defaulting to yes, and headless CI skips it entirely.

  • 已由理論轉為在野：CurXecute（CVE-2025-54135，CVSS 8.6）示範 Slack 訊息經已核准 MCP 改寫 Cursor 全域設定；MCPoison（CVE-2025-54136）利用「信任綁名稱而非內容」打團隊；2026-06 Miasma 蠕蟲在 73 個 GitHub 倉庫植入設定；Amazon Q 兩個 CVE（2026-12957/12958）可竊 AWS 憑證。

The class is operational: Miasma planted configs across 73 GitHub repos, and two Amazon Q CVEs enabled cloud-credential theft.

  • 【替代假設】若客戶端普遍實作簽署清單、描述掃描與動態工具範圍（Microsoft 2026-06 指引），且供應商強制重新核准（Cursor 1.3.9 起設定變更需重批），36.5% 基準只適用於未修補版本與未啟核准流程的部署；反之若 agent 持續以 auto-run 運行，唯一有效控制回到人工逐次確認。

If signed manifests, metadata scanning and dynamic scoping are adopted and vendors force re-approval, 36.5% applies only to unpatched, no-approval deployments; with auto-run always on, only per-action confirmation remains effective.

潛在影響 / Potential Impact

  • 【已披露事實】Miasma 蠕蟲以一組設定檔命中 73 個 GitHub 倉庫；Amazon Q 兩個 CVE 令惡意倉庫取得開發者環境繼承的 AWS 憑證。

Fact: Miasma hit 73 GitHub repos with one config set; two Amazon Q CVEs gave malicious repos access to AWS credentials inherited from the developer environment.

  • 【推論】放大倍數可量化：受影響程序繼承 AWS key、CLI token 與 SSH agent socket，攻擊面由個人機擴至建置環境；以 40 人團隊計，單次投毒可同時暴露 40 套以上憑證。此數字按 Miasma 實例推算，非統計估計。

Scaled to a 40-engineer team, one poisoning event exposes 40-plus credential sets.

  • 【推論】成本落在未基準化的審查工時：CSA 建議把任何 MCP 設定變更視為 code review 事件；但此類變更尚無對應 SBOM 式雜湊校驗標準，成本由各團隊自行承擔，本題未找到公開基準可量化。

Treating MCP-config changes as review events adds dependency-review-equivalent work, but no hash-verification standard exists and no public benchmark quantifies it.

  • 【推論】對非工程領域的啟示：描述欄就是政策執行點：機制在醫療、客服、財務代理中放大，因為「無痕執行加正常回覆」正是欺詐所需性質；AgentDojo 實測 97 個真實任務、629 個安全測試，顯示現有注入攻擊打破部分但非全部安全屬性。本題未找到可直接套用於非工程領域的量化估計。

Silent execution with normal replies is exactly what fraud needs, so the mechanism amplifies in healthcare, finance and support agents; no transferable quantitative estimate was found there.

簡評 / Commentary

可信度中等偏高。1,899 與 67,057 兩個生態掃描是一手可覆核；但 36.5% 來自 45 個伺服器樣本，外推整個生態需保留空間。「規格不要求驗證描述」是設計現實而非漏洞判定，CSA 視之為供應鏈資產。缺口：73 個倉庫實際被開啟的比例、被竊憑證的後續濫用數、註冊表審查與投毒率的因果量化。

Confidence is moderate-to-high: the two ecosystem scans are primary and checkable, but 36.5% rests on 45 servers. Gaps: the fraction of the 73 repositories actually opened, downstream misuse of stolen credentials, and no quantified causal link between registry vetting and poisoning rates.
